# Decisões técnicas

Cada decisão relevante ganha uma linha: data, decisão e motivo. As que dependem dos sócios estão marcadas com **[sócios]**.

| Data | Decisão | Motivo |
| --- | --- | --- |
| 2026-11-13 | Monorepo com **npm workspaces** (não pnpm). | Node 26 não traz mais o corepack; npm já vem instalado e resolve workspaces sem ferramenta extra. |
| 2026-11-13 | **TypeScript 5.9** fixo (não o 7). | O TS 7 (port nativo) ainda não tem a API JS que o Next usa para checar tipos no build. |
| 2026-11-13 | Next.js 16 (App Router) + React 19 + Tailwind 4 + Zod 4 + Vitest 5. | Versões atuais estáveis; Tailwind 4 com tokens em CSS (`@theme`) casa com o design system Terra Neutra. |
| 2026-11-13 | **Uma camada de banco, dois motores**: PGlite (Postgres em WASM) local/demo/testes e Postgres do Supabase via `postgres.js` em staging/produção. | O mesmo SQL, as mesmas migrations e a mesma RLS rodam nos dois. Permite testar RLS de verdade sem Docker e manter o modo demo sem nenhuma integração. |
| 2026-11-13 | RLS aplicada em toda consulta do lojista com `set local role authenticated` + `request.jwt.claims` (o mesmo mecanismo do Supabase). | A RLS do banco é a fonte da verdade do isolamento, não o código da aplicação. | 2026-11-13 | Auth: Supabase Auth (REST `/auth/v1`) quando `SUPABASE_URL` existe; login local com scrypt quando não. | 2026-11-13 | Telefone e e-mail cifrados na aplicação (AES-256-GCM, `APP_ENCRYPTION_KEY`) + HMAC para casar cadastros. | LGPD: dado pessoal cifrado em repouso independente do provedor; o hash permite deduplicar sem decifrar. |

| 2026-11-13 | Grupo de comparação sorteado com semente = id da missão (Fisher–Yates determinístico). | Reprodutível e auditável. |
| 2026-11-13 | Atribuição: pedido de quem recebeu, depois do dia do envio e até o fim da janela (7 dias). Grupo de comparação < 20 → usa a taxa de clientes parecidas e marca a comparação como fraca (hipótese). | PRD 2.8. |
